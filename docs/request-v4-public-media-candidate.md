# V4 candidate, phase 1
Disabled by default. No production deployment, DNS, bucket permissions, R2 writes or deletions. Do not expose the IMAGES bucket. The existing V1 CDN meta must remain unset unless separately audited.
The V4 eligible canonical URLs are exact approved contact revisions, exact approved workspace tag/emoticon/mini keys, and known character profile paths with explicit revision. Other workspace paths, unversioned mutable profile paths, achievements, Wardogs, external live images and unversioned contacts fall back unchanged. No public inference from path alone. For any future scope expansion, prove public reference, safe content, immutable revision and removal policy.
Offline builder: node scripts/build-media-v4-catalog.mjs approved-inventory.json output-directory. Inventory format: {"origin":"https://media.example.com","entries":[{"publicApproved":true,"url":"/media/contact/example?v=1&h=0123456789abcdef0123456789abcdef&r=2","file":"example.png","type":"image/png","group":"optional-visible-group"}]}. Builder writes content-addressed bytes and optional bounded packs, never uploads. For release, audit and upload only approved objects to a separate bucket, with correct MIME and immutable caching, public GET CORS from scheduler, and no credentials. Catalog must be published atomically with SW change after upload verification. A pack is raw concatenated bytes, no decompression; 4 MiB pack and 32-member grouping are transport limits, not cache quotas.
The SW checks existing canonical cache first, joins simultaneous per-URL fills, and requests CDN only for explicit catalog entries. Bundle only if at least four distinct demanded images cover 80% of its bytes; sparse demand fetches individual images. SHA-256 and exact size are checked before returning a public immutable response under the V3 canonical cache key. Wrong or missing bytes fall back to canonical route; failed direct objects and packs have a bounded-time cooldown. No background polling or forced prefetch. V3 cache entries retained. New or changed canonical revisions absent from the published catalog intentionally fall back until the catalog is refreshed. This phase does not yet automate public publication from save/delete paths. For deferred approved contact images, an opt-in page bootstrap handles first uncontrolled visits using the same verified CDN delivery, populating the same V3 cache without waiting for SW control. Other uncontrolled paths still use canonical routes. Enable both V4_PUBLIC_MEDIA_ENABLED in SW and MWS_PUBLIC_MEDIA_V4_ENABLED=1 in Worker environment only after approval. The optional prior catalog argument emits a publication plan of new content hashes and objects requiring retirement review; it never deletes or uploads objects. Actual browser and full regression tests and visibility audit required before enabling. Do not set V4_PUBLIC_MEDIA_ENABLED true in production before approvals.
